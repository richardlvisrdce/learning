
if we store passwords as plaintext, a database breach will give instant access to everything
so we store passwords as hashes..

What does a cool hash function look like?
 - one-way function, can't be reversed (has to be brute-forced)
 - deterministic, same input always gives same output
 - fixed length, no matter the input size (eg. MD5 is 32 chars)
 - collision resistant, hard to find 2 inputs with same output (not MD5, not SHA1)

problematic hash functions
 - MD5 a lot of collisions, very large rainbow tables (already precomputed common values)
 - SHA1 - faster than SHA256, deprecated
 - SHA256 - still secure, but not ideal for password storage (fast, so brute-force is easier)

Well, we lied a bit...
 - there are good hash functions that don't fit all of the "cool" criteria
 - bcrypt
    - length is about 60 chars, $2*$ prefix
    - good for passowrds
    - deliberately slow, cost is configurable (cost = amount of hashing iterations, more = securer)

 - Argon2
    - Password Hashing Competition 2015 winner 
    (still deemed the best, especially the Argon2id variant)
    - length is variable
    - good for passwords
    - modern standard, memory hard, configurable

Salting
 - unique random string generated for each user 
   and combined with their password before hashing
 - stored_value = hash(password + salt)   # this is very simplified and not how argon does it


Hash cracking
 - first check crackstation.net or hashes.com if they recognize the hash
 - then we use hashcat or john the ripper to brute-force it

 - you will need a wordlist (eg. rockyou.txt) 
 - if you lost your wordlist, find it with find!
 - find / -name rockyou.txt 2>/dev/null

 - johntheripper workflow
    - identify the hash type
      hashid '<HASH>'

    - get the actual hash type for john (eg. Raw-MD5)
      john --list=formats | grep -iF "HASH_TYPE"
 
    - now bruteforce
      john --format=<ACTUAl_HASH_TYPE> --wordlist=<WORDLIST> hash.txt
 
 - hashcat workflow
    - identify the hash type (this will give us hashcat's mode number)
      hashcat --identify '<HASH>'   # if this fails, try hashid and google the hashcat mode number
    
    - it might give you more results, try the most likely
    - eg. 32 characters - we try MD5 
      hashcat -m 0 -a 0 -o cracked.txt hash.txt /usr/share/wordlists/rockyou.txt
      - not MD5? try NTLM, ...

 - mask attacks
    - if you are sure that the password has a certain structure (better than completely random bruteforce)
    - eg. lowercase-only 6-character
    - this is actually 26^6 = 308,915,776 combinations (a lot more than rockyou.txt)
    - eg. passwords like Summer2026! (capital letter, 6 lowercase letters, 4 digits, 1 special character)
    - hashcat mask: ?u?l?l?l?l?l?d?d?d?d?s
